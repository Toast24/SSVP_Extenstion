# Code Overview — SSVP module table of contents

Canonical tree: `SSVP/ssvp/03_code/`. This is a plain-English map of what each
file does — for setup/run instructions see
[`03_code/README.md`](../SSVP/ssvp/03_code/README.md); for the merge history
behind the current script layout see [`MERGE_PLAN.md`](MERGE_PLAN.md) and
[`HANDOVER.md`](HANDOVER.md).

## scripts/

### aggregate_run22_results.py
Aggregates the run22 caption-comparison experiment's scattered outputs into one JSON and a short Markdown summary. `_load_json` safely reads optional JSON files, and `_summarize_training_metrics` picks the best epoch (lowest `val_loss`) and the final epoch from a training-metrics history. `main()` walks the `cable`/`transistor`/`capsule` categories under `runs/run22_caption_compare`, merges per-category eval results, training summaries, a WinCLIP placeholder, and BLIP caption reports into `aggregate_results.json`, then writes a minimal `run22_summary.md`. Purely a post-hoc reporting/glue script, not part of the training or inference path.

### caption_compare.py
Compares BLIP-generated captions against a simulated "AnomalyGPT" baseline for qualitative reporting. `run_evaluate_captions` shells out to `evaluate_captions.py` to produce the model's captions and a `caption_before_after_report.json`; `synthesize_anomalygpt_outputs` then fabricates a stand-in AnomalyGPT caption per image by doing a naive string substitution (`anomaly`→`defect`, `at`→`located at`) on the model caption, saving `gt.txt`/`model.txt`/`anomalygpt.txt` per image. Used to produce side-by-side caption comparison artifacts for reports since no real AnomalyGPT integration exists.

### caption_utils.py
Shared, dependency-light helpers for building ground-truth caption *targets* (not generated captions) from dataset metadata, extracted from `run_full_pipeline.py` so `evaluate_captions.py` and `caption_compare.py` can import them without a circular dependency. `_build_domain_caption` produces a generic "photo of X with/without a visible defect" string; `_mask_to_spatial_location` converts a ground-truth/predicted mask into a coarse 3x3 grid location label (e.g. "upper left", "center"); `_build_spatial_defect_caption` combines defect type + location into a caption like "anomaly at lower right"; `_build_caption_target` picks between "spatial" and "domain" caption styles based on config.

### compare_against_baseline.py
A CI/experiment gate that compares a candidate run's metrics against a baseline run and fails (exit code 2) if any metric drops more than `--max_drop` points. `_extract_clean_metrics`/`_extract_noise_metrics` pull AUROC/F1/AP (image and pixel level) from `results.json` and `robustness_report.json`; `_compare_metrics` computes per-metric deltas and the worst-case delta. Used by ablation/compression pipelines to automatically decide whether a compressed/distilled/pruned model is "good enough" to keep.

### evaluate_captions.py
The core BLIP captioning benchmark: for N sampled test images it runs three caption variants — a no-hint baseline, a domain-fine-tuned BLIP model, and captions synthesized directly from predicted/ground-truth anomaly masks — and scores each against BERTScore, an anomaly-presence exact-match, and a spatial-location match, with optional NLI entailment scoring via `facebook/bart-large-mnli`. `_evaluate_variant` orchestrates a single variant's caption generation + scoring; `main()` loads an `SSVP` checkpoint when `--synthesize_from_predicted_map` is set (to attach predicted masks to metadata), builds an `MVTecDataset` test split, runs all three variants, and writes `caption_before_after_report.json` plus an optional cross-domain generalization report. *(Ported from SSVPREFAC — see [MERGE_PLAN.md](MERGE_PLAN.md).)*

### evaluate_noise_robustness.py
Evaluates a trained SSVP checkpoint's robustness to heavy synthetic image corruption (Gaussian noise, salt-and-pepper, blur, JPEG artifacts via `_add_heavy_noise`/`_jpeg_degrade`) and compares against previously computed clean-image results. `evaluate_noisy` runs the model on noised versions of the test set, computes image- and pixel-level metrics plus optional threshold-based accuracy/F1 using calibration thresholds, and saves visualizations for a few anomalous samples; `build_robustness_report` computes clean-vs-noisy deltas. Invoked as a pipeline stage after standard inference to quantify the noise-robustness ablation.

### generate_reports.py
Turns raw run22 artifacts (training metrics CSVs/checkpoints, WinCLIP metrics, per-image caption outputs) into human-readable Markdown reports: `write_training_summary`, `write_winclip_comparison`, and `write_caption_comparison` each scan a subdirectory and emit one `.md` file, and `main()` also seeds a `changes_from_run21.md` changelog template if missing. Pure reporting glue, downstream of `aggregate_run22_results.py`/training runs. *(Ported from SSVPREFAC.)*

### inference.py
The main evaluation script for a trained SSVP checkpoint on the MVTec-AD test set. `evaluate()` runs the model per-batch (optionally with horizontal-flip test-time augmentation), post-processes anomaly maps (`postprocess_anomaly_map`), accumulates per-category and overall image-level (AUROC/F1-Max/AP) and pixel-level (AUROC/PRO/AP) metrics, saves visualizations for anomalous samples, and optionally applies calibrated thresholds for accuracy/precision/recall/F1. `print_results` renders a formatted results table; `main()` wires up CLI args, loads the checkpoint/model/dataset, and writes `results.json`. This is the standard "did my model work" entry point, called both directly and as a stage inside `run_full_pipeline.py`.

### live_demo_noisy_folder.py
An end-to-end demo script that runs segmentation + captioning on an arbitrary folder of (possibly noisy) images rather than a formal MVTec split. It loads a checkpoint, runs inference per image to get an anomaly heatmap/score/predicted label (`infer_defect_hint` guesses a defect label from the parent folder name), saves heatmap/mask/overlay PNGs (`save_segmentation_artifacts`) and a titled visualization, calls `generate_captions` from `run_full_pipeline.py` for natural-language captions (with INT8 text-transformer compression on by default), and writes a `demo_summary.json` with per-image scores, thresholds, and caption text. Intended as a user-facing/demo-ready inference tool.

### path_utils.py
Centralizes all repo-relative path constants (`SCRIPTS_DIR`, `CODE_DIR`, `SRC_DIR`, `DATASETS_DIR`, `RESULTS_DIR`/`LOGS_DIR`, etc.) computed from `__file__`, so every other script gets consistent paths regardless of the caller's working directory. `ensure_import_paths()` inserts `src/` (and optionally `scripts/`) onto `sys.path` so `from models...`/`from data...` imports work without a package install; `default_config_path()` resolves `configs/default.yaml`. Imported by virtually every other script in `scripts/`.

### prepare_cable_split.py
Builds a randomized 70/20/10 train/test/val re-split of one or more MVTec categories from the original MVTec train/test/ground_truth layout, used because MVTec's native split conflates "test" with what should be held-out validation. `split_counts` computes bucket sizes with minimum-1 guarantees; `resolve_category_root` handles MVTec's occasional doubly-nested folder naming; `main()` pools all "good" images (from original train+test) and all defect images (with matching masks via `find_mask`) per defect type, shuffles with a seeded RNG, and copies files into the new `train/test/val/ground_truth` layout with renamed stems to avoid collisions, writing a `split_summary.txt`. This is the data-prep step that produces `cable_resplit` and similar directories referenced throughout the other scripts.

### run_ablation_matrix.py
Runs a small matrix of robustness/architecture ablations (no consistency loss, no TTA, no robust post-processing, weak augmentation, LoRA without consistency) by deep-merging each variant's config overrides onto a base config and invoking `run_full_pipeline.py` as a subprocess per variant. `collect_variant_metrics` reads back each variant's clean/noisy eval JSONs and clean→noisy deltas into a compact summary dict, and `main()` writes a combined `ablation_summary.json` (also mirrored under `ABLATION_JSON_DIR`). Used to systematically probe which training/eval knobs matter for robustness.

### run_anomalyclip_baseline.py
A stub/placeholder for running the third-party AnomalyCLIP zero-shot baseline against the project's data split, for comparison purposes. `run_anomalyclip_on_split` documents the intended subprocess call into an external `AnomalyCLIP` repo but currently just writes hard-coded simulated metrics (`auroc: 85.0` etc.) in the project's standard results schema; `main()` loops over categories and writes a combined summary. Not a real baseline yet — explicitly a simulated placeholder pending deeper integration. *(Ported from SSVPREFAC.)*

### run_full_pipeline.py
The central orchestrator tying together training, evaluation, noise-robustness testing, and BLIP captioning into one command, and also home to the shared `generate_captions()` function used by several other scripts. Helper functions build rich domain captions from ground-truth mask geometry (`_describe_mask_location`, `_build_domain_caption`, `_build_generation_prompt`); `_collect_caption_finetune_records` samples training images and generates their captions; `_finetune_caption_text_model` runs a short supervised fine-tune of BLIP's text decoder on those (image, caption) pairs; `_apply_int8_dynamic_quantization_to_caption_text_transformer` optionally quantizes the caption model's text transformer to INT8 for CPU inference speed/size. `generate_captions()` loads BLIP, optionally fine-tunes and/or quantizes it, then generates a caption per image (falling back to a synthesized domain caption if generation is empty). `sample_and_save_visuals` samples random test images, runs the segmentation model plus captioning, and saves visualization+caption pairs. `main()` runs `train.py` → `inference.py` → `evaluate_noise_robustness.py` → caption/visualization sampling as subprocess stages, each independently skippable via flags.

### synthesize_caption_files.py
A small one-off utility that reads an existing `caption_before_after_report.json` (from an older/legacy run layout using a `baseline` key) and expands its captions/references into per-image `gt.txt`/`model.txt`/`anomalygpt.txt` files, using the same naive AnomalyGPT-simulation substitution as `caption_compare.py`. Essentially a standalone re-implementation of `caption_compare.py`'s synthesis step for reports that predate the current pipeline. *(Ported from SSVPREFAC.)*

### test_shapes.py
A CPU-only, no-GPU-required shape/sanity test suite for the model's trainable modules, run as a script (not pytest). It individually instantiates and forward-passes `ATFBlock`, `HSVS`, `VCPG`, `VTAM`, and `SSVPLoss` with dummy tensors and asserts their output shapes match the paper's specification, then runs `test_full_trainable_pipeline()` which chains HSVS→VCPG→VTAM→loss→backward to confirm gradients flow. Acts as a lightweight regression test to catch shape-breaking changes to the architecture without needing real data or a GPU.

### train.py
The main SSVP training loop implementing "Algorithm 3" from the paper: gradient-accumulated, mixed-precision training with dual learning-rate groups (prompts vs. network), optional consistency regularization (`_perturb_for_consistency` + MSE on global features under noise), optional knowledge distillation from a frozen teacher checkpoint (`setup_distillation_teacher`, `compute_distillation_loss`), and cosine-annealing LR scheduling with warmup (`setup_scheduler`). `train_one_epoch` runs the forward/backward/step loop with all optional loss terms; `validate` computes held-out loss on a train-derived split (to avoid test leakage); `derive_validation_thresholds`/`_robust_threshold` calibrate image- and pixel-level decision thresholds on the validation set (optionally jointly against a noisy version of validation to pick a robust threshold) and save them to `calibration_thresholds.json`. `main()` wires up data loaders, model, optimizer, early stopping, checkpointing (`save_checkpoint`), and writes `training_metrics.json`/`training_summary.json` — the latter now also includes a `dataset_statistics` block (see [`src/data/mvtec.py`](#srddata) below) ported from SSVPREFAC. This is the core training entry point invoked directly and via `run_full_pipeline.py`.

### train_run22.py
An orchestration wrapper that reproduces the "run22_caption_compare" experiment: prepares per-category dataset roots from either the `cable_resplit` split or a JSON split manifest (`prepare_category_root`, which rebuilds train/val/test/ground_truth subfolders by copying files listed in a split JSON), writes a per-category temp config forcing `epochs=20` with early stopping disabled, and calls `run_full_pipeline.py` per category (`run_category`), copying the resulting checkpoint to `best.pt`/`last.pt` and writing a `metrics.csv`. `main()` deep-merges the canonical `default.yaml` with any user-supplied override config (see `configs/run22_override.yaml`) before dispatching all requested categories. *(Ported from SSVPREFAC.)*

## scripts/_deprecated/

Moved out of the primary workflow (still runnable) per `docs/MERGE_PLAN.md` Phase 2.

### run_compression_gate_pipeline.py
A two-stage compression-method runner: for each candidate compression method (depth/differentiated head pruning, 53M/43M distillation students), it first runs a short 3-epoch "prelim" training+eval stage and gates on `compare_against_baseline.py`'s max-drop check; only if that gate passes does it promote to a full 15-epoch run and gate again. `run_train_with_stall_workaround` is a defensive wrapper around `train.py` that polls for completed training artifacts and force-terminates the subprocess if it hangs after writing `best_model.pth` (a known calibration-stage stall bug). Superseded by `run_ablation_matrix.py`/`run_staged_distillation.py`, retained for reference.

### run_head_sanity_tests.py
A quick (3-epoch) sanity check across four head-only pruning/LoRA variants (width pruning, depth pruning, differentiated pruning, LoRA rank-2) applied only to the trainable heads (HSVS/VCPG/VTAM), verifying training actually completes and checkpoints are produced (`collect_training_status`) rather than evaluating accuracy. A precursor/smoke-test to the fuller `run_ablation_matrix.py`.

### run_llm_compression_prompt_tests.py
A fast caption-side experiment runner comparing four variants — baseline, INT8-quantized caption text transformer, domain-fine-tuned prompts, and both combined — by invoking `run_full_pipeline.py` in `--skip_train --skip_eval` mode so only caption generation runs. `run_variant` times each run and counts produced visualization/caption files, and records the fine-tune loss summary if present. Predecessor to fine-tuning/quantization options that were later folded directly into `run_full_pipeline.py`/`live_demo_noisy_folder.py`.

### run_staged_distillation.py
A hard-coded two-stage distillation driver: trains/evaluates a 53M-parameter distilled student against the run21 baseline, and only if it passes the `compare_against_baseline.py` gate, uses its checkpoint as a teacher to train/evaluate a further-compressed 43M "re-distilled" student, gating again. Fixed paths (`run21_resplit_15es`, `ssvp_student_53m_distill.yaml`, etc.) make it a one-off experiment script rather than a general tool; superseded by the more configurable `run_compression_gate_pipeline.py`.

## src/data/ {#srddata}

### `__init__.py`
Re-exports `MVTecDataset` and `DualResizeTransform` as the package's public API for the `data` subpackage.

### mvtec.py
Defines `MVTecDataset`, the PyTorch `Dataset` for MVTec-AD-style anomaly detection data, supporting `train`/`val`/`test`/`all` splits and both "good-only training" and "train on all defect types" modes (`train_all_types`, used for anomaly-supervised training). `_load_samples`/`_load_split_all_types` walk category directories, pairing anomalous images with ground-truth masks via `_find_mask`; `__getitem__` loads image+mask through the configured transform (plain `DualResizeTransform` or `AugmentedTransform`) and returns image/mask/mask_full/label/category/defect_type/path. `get_mvtec_dataloaders` builds simple train/test loaders; `get_mvtec_train_val_dataloaders` builds train/validation loaders either from an explicit `val/` split or by randomly slicing the train split (with a validation-only, unaugmented copy substituted in to avoid leaking augmentation into val metrics). `log_dataset_statistics` prints/returns per-category and per-defect-type sample counts, used for P-PRO diagnostics *(ported from SSVPREFAC — see [HANDOVER.md](HANDOVER.md))*. `MVTEC_CATEGORIES` enumerates the 15 standard MVTec-AD categories.

### transforms.py
Defines the image/mask preprocessing pipeline shared by CLIP and DINOv2 (both use 518×518 input / patch 14 → 37×37 feature grid). `DualResizeTransform` resizes+normalizes the image and produces both a mask sized to the feature grid (37×37, for loss) and a full-resolution mask (for eval), binarizing at 0.5. `AugmentedTransform` subclasses it to add training-time-safe augmentations (hflip, color jitter, sharpness, Gaussian blur, then post-normalization additive Gaussian noise via `AdditiveGaussianNoise`) while explicitly avoiding any geometric transform that would misalign the mask.

## src/models/

### `__init__.py`
Re-exports `SSVP`, `DualBackbone`, `HSVS`, `VCPG`, `VTAM` as the models subpackage's public API.

### backbones.py
Defines the three frozen encoders that feed the trainable heads. `CLIPFeatureExtractor` wraps an OpenCLIP ViT-L/14 visual encoder, interpolates its positional embeddings to match the target 37×37 grid if needed, registers forward hooks on specified transformer blocks to grab multi-scale patch-token features plus a global CLS token, and freezes all parameters. `DINOFeatureExtractor` does the same for a DINOv2 ViT-L/14 loaded via `torch.hub` (with a local-cache fallback for offline use), acting as a stand-in since DINOv3 wasn't available. `CLIPTextEncoder` wraps the frozen CLIP text transformer's low-level pieces (token/positional embeddings, transformer, projection) to encode already-built prompt *embedding* sequences (rather than tokenized text) via `encode_text_embeddings`, with optional CPU-only INT8 dynamic quantization; `get_token_embedding` looks up raw vocabulary embeddings for building class-name tokens. `DualBackbone` bundles all three and exposes `extract_visual_features`, leaving autograd behavior (no_grad vs. LoRA-enabled) to the caller.

### hsvs.py
Implements the Hierarchical Semantic-Visual Synergy (HSVS) module that fuses CLIP's global semantics with DINOv2's fine-grained structure. `ATFBlock` (Adaptive Token Features Fusion) performs bidirectional cross-attention — CLIP-queries-DINO and DINO-queries-CLIP — projects each into a shared subspace, concatenates+LayerNorms both attention outputs, fuses them through an MLP, and adds a residual from the CLIP features. `HSVS` applies one `ATFBlock` per feature scale (4 local scales + 1 global CLS-token scale by default), handling spatial-dimension mismatches between CLIP/DINO patch grids via bilinear interpolation, and returns a global synergistic feature plus a list of per-scale local synergistic feature maps consumed by VCPG/VTAM.

### lora.py
A minimal, dependency-free LoRA (Low-Rank Adaptation) implementation for `nn.Linear` layers. `LoRALinear` wraps a base Linear layer, adds trainable low-rank matrices `lora_A`/`lora_B` (with Kaiming-init A and zero-init B so it's a no-op initially) and freezes the base weights by default; `forward` adds the scaled low-rank correction to the base output. `apply_lora_to_module` recursively walks a module tree and replaces matching `nn.Linear` children with `LoRALinear`, optionally filtered by name substrings or a custom predicate — used by `SSVP.__init__` to selectively inject LoRA into the frozen backbones or the trainable heads for parameter-efficient fine-tuning experiments.

### losses.py
Defines the full SSVP training objective. `FocalLoss` handles pixel-class imbalance in segmentation; `DiceLoss` and `ProOrientedLoss` (a differentiable surrogate for the PRO evaluation metric, penalizing false-positive rate on normal regions) are optional additional segmentation terms; `VAELoss` computes the VAE ELBO (reconstruction MSE + KL term) regularizing the vision-conditioned prompt generator's latent space; `MarginRegularization` keeps vision-conditioned prompts from drifting too far (via cosine-similarity margin) from their initial semantics. `SSVPLoss` composes all of the above per the config's loss weights into a single `forward(outputs, targets)` that returns a total scalar loss plus a dict of individual components for logging, including an optional denoiser reconstruction term when the denoising autoencoder is enabled.

### ssvp.py
The top-level `SSVP` model class that wires together the frozen `DualBackbone`, then the trainable `HSVS` → `VCPG` → `VTAM` pipeline (Algorithm 1 in the paper), plus several optional experimental features. It optionally instantiates a lightweight U-Net-style `DenoisingAutoencoder` that can be trained to denoise inputs before the frozen backbones (`_build_noisy_inputs`, `_maybe_denoise_inputs`) and supports structured head-only pruning (`_apply_head_pruning`: width-wise via `torch.nn.utils.prune.ln_structured`, depth-wise by truncating ATF/gate module lists, or "differentiated" per-module ratios) and selective LoRA injection into the backbone and/or HSVS/VCPG/VTAM heads (with a safety check that VTAM is never LoRA-wrapped unless explicitly requested, since it must stay fully trainable). `get_trainable_params` splits parameters into a high-LR "prompt" group (VCPG's prompt bank + alpha gate) and a lower-LR "network" group (everything else trainable, including LoRA adapters). `get_class_token_embedding` builds a class-name embedding from frozen CLIP token embeddings, with a cache. `forward()` runs the full pipeline: optional denoising → frozen (or LoRA-augmented) backbone feature extraction → HSVS fusion → VCPG prompt generation → VTAM anomaly map/score, returning a dict consumed by `SSVPLoss` and the eval scripts.

### vcpg.py
Implements the Vision-Conditioned Prompt Generator (VCPG). `PromptBank` holds learnable "[V]_bg + [V]_state (+ [CLASS])" prompt embeddings, with background vectors shared across normal/abnormal prompts and separate state vectors per class. `VAEModule` encodes the global synergistic feature into a Gaussian latent (`encode`/`reparameterize`/`decode`) providing a "visual latent bias." `TextLatentCrossAttention` lets the initial text prompts attend over tokenized latent-space vectors to produce an injection delta. `VCPG.forward` ties these together: build initial prompts → VAE-encode the image's global feature → cross-attend text against the latent → gate the injection with a learnable scalar `alpha` and LayerNorm to get final vision-conditioned prompts, returning both final and initial prompts (for the margin regularization loss) plus VAE outputs. `get_aggregated_prompt_features` pools the multi-prompt, multi-token embeddings down to single normal/abnormal vectors, via mean pooling or a learned attention-weighted pooling.

### vtam.py
Implements the Visual-Text Anomaly Mapper (VTAM), which turns the fused visual features and vision-conditioned prompts into a final anomaly map and score. `AnomalyMoE` computes a per-scale anomaly probability map from cosine similarity between local visual features and normal/abnormal prompt embeddings (temperature-scaled softmax), applies a learned global "scale gate" (which scale/layer matters more) and a per-layer local spatial gate (1×1 conv + sigmoid), optionally reweights by an entropy-based per-expert confidence, and fuses everything into one anomaly-probability map. `VTAM.compute_score` combines a global cosine-similarity-based score with a robust local score (quantile+mean pooling of the anomaly map), fused via either a fixed or dynamically-predicted (entropy-aware) gamma, producing the final `[B]` anomaly score, and converts the fused probability map into logits for loss compatibility.

## src/utils.py

Grab-bag of evaluation/visualization/config utilities used across training and inference. `compute_image_level_metrics`/`compute_pixel_level_metrics`/`compute_pro_score` implement the paper's evaluation protocol (AUROC, F1-Max, AP at image level; AUROC, PRO, AP at pixel level, with `compute_pro_score` doing full per-connected-component overlap integration up to FPR=0.3). `postprocess_anomaly_map` upsamples raw model output to full image resolution and applies optional percentile clipping, Gaussian smoothing, and median filtering. `visualize_results` renders a 2- or 3-panel (image / heatmap / ground truth) matplotlib figure to disk; `denormalize_image` reverses ImageNet normalization back to a uint8 RGB array. `load_config` reads a YAML config (with a UTF-8→cp1252 fallback), and `set_seed` seeds Python/NumPy/Torch (and forces deterministic cuDNN) for reproducibility.

## configs/

`configs/default.yaml` is the canonical run21-baseline configuration for the whole pipeline: it sets backbone choice/sizes (CLIP ViT-L/14 + DINOv2 ViT-L/14, both frozen, 518px/37-grid), HSVS/VCPG/VTAM architecture hyperparameters (projection dims, prompt-bank sizes, temperature/gamma), loss weights (focal/VAE/margin, with the newer PRO-surrogate and Dice terms disabled by default to match run21 behavior), training hyperparameters (15 epochs, small batch size with gradient accumulation for a small GPU, dual learning rates, early stopping, optional consistency/augmentation blocks all off by default), data paths/sizes, evaluation post-processing and calibration settings, noise-robustness test parameters, BLIP captioning settings (model name, prompt, optional domain fine-tuning and INT8 quantization, all off by default), and a disabled-by-default LoRA block.

`configs/run22_override.yaml` is a small deep-merge override on top of `default.yaml` used by `train_run22.py`/run22-related scripts: it bumps training to 20 epochs with early stopping disabled and `train_all_types: true`, and turns on caption domain fine-tuning (1 epoch, batch size 4, lr 2e-5, up to 96 samples) for the run22 caption-comparison experiment.
